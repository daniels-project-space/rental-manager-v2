# Verification failure and written rollout consent

Daniel explicitly instructed on 2 October 2026 that this audit must be easy to migrate to real Hygglo chats, but never activated there without explicit written consent. Deploying Lab/app improvements does not authorize that transition. `renter_bot_runtime.ts` blocks both backend generation and the direct draft HTTP endpoint for real threads before leases, context retrieval or provider calls. Real cancellation and messaging are not implemented by this phase.

The Lab simulates a final platform verification failure only when a booking awaits verification. One transaction cancels the Lab booking, preserves its basket, records one explanation in Lab history and issues a seven-day basket referral. Repeated events do not issue another code or message. Pending documents, payment and renter assertions cannot trigger the event. The failed basket is closed to changes and resets.

A friend supplies the opaque referral code through the Lab control and starts a separate empty inquiry. Names alone do not establish a relationship. Restoration rechecks listing identities, quantities, current account pricing, multi-day tiers and complete basket stock. Expired codes, past dates, wrong accounts, unresolved items and unavailable stock fail without partially rebuilding or consuming the referral. Successful redemption binds the code to one destination thread; retrying does not duplicate items. The friend inherits no verification, payment, approval or original renter's personal details. Lab history tells the shared bot engine why this basket exists.

The recommendation tool's `lower_value_only` filter compares recorded positive replacement costs, not hire prices. Unresolved original identities or unknown costs produce no lower-value claim. Existing category, mount, capability and stock requirements still apply. An existing verified account may need fresh booking checks, and lower value never guarantees approval. Lens framing/optical suitability still requires the broader recommendation audit.

Official policy reviewed: [verification failures](https://help.hygglo.info/en/articles/12701785-managing-your-verification), [per-booking verification](https://help.hygglo.info/en/articles/10455222-how-verification-works-on-hygglo), [value-dependent checks](https://help.hygglo.info/en/articles/12890803-hygglo-care-for-borrowers), [UK terms](https://hygglo.com/uk/tos), particularly sections 9.2 and 9.12. A friend must book from their own account and take responsibility for renting on another person's behalf.

This is an operator-triggered simulation of an authoritative event. Connecting platform events, accepting referral codes in live renter conversations and creating actual bookings remain future adapter work, explicitly gated by Daniel's written consent. The broader bot audit and physical handset push verification remain unfinished.
