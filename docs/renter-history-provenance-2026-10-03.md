# Renter history retains its source and scope

The successful draft path passed the internal prior-rentals-with-us count (excluding the current thread) to persistRenterStats, which overwrote the same total_rentals_count populated by Hygglo's customerCompletedOrders trust refresh. It also persisted a prior reservation-created timestamp as last_rental_at. A first-time business customer could overwrite a substantial platform history with zero. The old business-history loop counted scheduled confirmed collections as rentals that had happened, and its prompt fallback mislabeled platform-wide counts as rentals with this business. The canonical API had hydrated renter context but omitted the actual profile/history from its model input.

The old writer is retired. Scoped Native persistRenterDNA resolves the current person and transcript, checks message/epoch/booking context, writes only tone data, and refuses to train a real profile from a Lab conversation. Caller-provided counters, dates and inferred DNA are not accepted. Historical statistics are not rewritten by drafting.

Existing total_rentals_count is retained as potentially contaminated legacy data. A dedicated platform_completed_rentals field is written by a valid nonnegative integer platform trust refresh, and bot consumers use that field instead of presenting the legacy value as verified. No historical counts were automatically migrated or repaired.

Both context producers share renterHistory: exact Native renter IDs/platform user IDs, indexed reads, contradiction exclusion, order deduplication and only actually in-use/overdue/completed bookings. Requests, payment, scheduled collection, cancellations, obsolete rows and the current thread do not establish prior rentals. Last-rental time comes from a valid past pickup/start date, never reservation creation. Missing identity produces unknown counts. The DTO explicitly separates platform-wide completed rentals from recorded business rentals; the actual SDK preserves it and canonical prompt hydration forwards it. Returning-customer wording no longer substitutes platform counts or claims an exact rental ordinal.

Validation: 52 focused registered/pure tests and project/backend typechecks cover provenance, identity merging, date/status filtering, stale writes, Lab isolation and fixture cleanup safety. One deployed owned profile fixture tested legacy-unknown output, a controlled Native trust snapshot of108, business count0, both actual context producers and actual SDK output parsing, no-op Lab tone learning, rejected counter input and retired old endpoint. Conversation, basket and owned profile remained consistent and were cleaned. No actual Hygglo HTTP call, real person update, rental write or model call. This is a controlled Native snapshot, not proof that a real platform profile was refreshed.

Proof: /root/rental-history-native-proof.json. The fixture helper derives its identity exclusively from an owned __probe__ thread, refuses foreign linked profiles, and cleanup deletes only its exact namespace. No real profile was used for write tests.

Limits: historical legacy-count repair, platform-refresh person binding/provenance timing, CRM/churn consumers of legacy fields, full-history completeness, tone-learning idempotency and fresh model wording under the new context remain open audit work.
