# Recover confirmations from stored Native edits

An accepted date edit or item removal could commit successfully, then leave the renter with no usable confirmation when the generated reply failed validation. Transport/HTTP errors and empty replies could also lose the tool receipt after its write, making another generation risk repeating work.

Recovery now verifies one stored Native addition, date change or removal against the original order, latest renter message, exact request key, unchanged prior ledger, current context and revision. Date edits preserve the same members, quantities and captured terms. Removals verify the exact product/quantity and stored removal identity; empty bookings retain review. Totals are independently recomputed using captured raw tiers and the shared Native whole-pound policy. Recovery creates a short factual confirmation and its price evidence from that order and runs the ordinary guard before saving it. The rejected candidate or transport failure remains visible in a recovery flag. No edit or model call is repeated.

Transport/HTTP and empty-reply recovery reads the Native ledger even if the provider omitted its tool receipt. A newer renter message or changed epoch prevents recovery. Unknown prices, unrelated or multiple edits, changed terms/baskets, closed rentals, invalid context and inconsistent sums retain review. Explicit model business escalations still retain their existing human review path.

A related price-parser defect misread “the updated booking total” for a single-item booking. The guard now recognises that full-booking subject and still checks its Native amount and period.

Validation: 218 focused tests across amendment proof, price claims, draft guard and reply review; final backend typecheck/deploy. No full-suite or local Next build repeat. Controlled failures exercised the actual registered generateDraft handler locally against deployed Native queries/mutations, replacing only the canonical HTTP provider response; no paid model calls. Six disposable cases: rejected date/removal replies, date transport failure, addition HTTP failure, empty date reply and newer inbound. Five recover correct £170/£144/£194, save current approval, retain independent Native price evidence and pass deployed send dry run after exactly one edit. The newer inbound correctly withholds the old confirmation. All fixtures cleaned. Only the failed empty-reply case was rerun after fixing its early return; original passing receipts retained in the aggregate. Proof: /root/rental-recovery-v2-native-aggregate-proof.json.

Still open: multiple edits and empty-booking cancellation recovery; explicit business escalations after partial work; remaining kit compatibility after removals; durable phone notifications and owner access cutover; broader stage, recommendation, inventory/spec and metrics audit. No claim of complete production readiness. Real Hygglo activation, messages and booking writes require separate explicit written consent.
