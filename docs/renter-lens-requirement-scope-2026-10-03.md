# Desired lens requirement scope — 3 October 2026

An actual production-model lab turn correctly said the TTArtisan 11mm is manual focus, recognised the confirmed booking and left the basket unchanged, but falsely claimed we do not own an autofocus wide-angle Sony E lens. Existing stock grounding withheld that reply. The turn cost $0.0076905; its response was not mocked.

A deployed Native query reproduced a deeper defect independently: explicit desired requirements (autofocus, wide-angle) conflicted with `manual focus` mentioned in a question about the current lens. The backend merged keywords across current-item identity and the entire renter message. It also collapsed absent reviewed specifications and proven mismatches into the same empty result.

The backend now accepts structured requirements for the desired alternative, without reinterpreting the current lens or every phrase in the conversation. Removed the unscoped keyword parser. Lens searches explicitly supply `lens_requirements`, including {} for generic browsing. Missing requirements return `requirements_not_specified` and no purported verified matches. Both automatic lens discovery callers now supply their unconstrained {} contract; the actual agent tool describes the scope.

Requirement assessment distinguishes verified matches, proven mismatches and missing reviewed properties. Owned, same-mount items missing relevant verification are returned separately as `lens_review_needed`, never as qualified alternatives. `lens_search_outcome` explains missing requirements, missing spec review or no verified match. Zero returned matches does not establish inventory absence or dated unavailability. Marketing, native mount, current basket, price and date-stock checks remain in place. No output regex rules were added.
