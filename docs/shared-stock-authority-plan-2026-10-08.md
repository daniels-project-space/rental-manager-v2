# Shared stock authority: implementation boundary still open

The canonical physical inventory already lives in Rental Manager. A coordinator in that same Convex deployment must serialize the complete proposed physical basket against capacity, repairs/owner blocks, confirmed/ongoing custody and all unresolved claims. Website local holds and authenticated snapshots remain projections; neither may independently approve a new stock commitment. This plan records source inspection, not a completed coordinator.

Observed callers:

- `src/hygglo-core/orders.ts:approve` delegates to `src/lib/hygglo-write.ts:acceptOrder`; `patchOrderAction` is the current outbound Hygglo PATCH choke point. Manual write gates have independent paths in the same module. Approval/date/item changes must participate; price-only changes, messages and ratings must not accidentally reserve stock.
- `src/lib/convex-service.ts:createConvexServiceClient` pins private worker transport to hearty-oyster-600 and uses owner service identity. Convex actions also invoke the shared write module, so a Next-only service-client adapter is insufficient. Internal action context and server worker transports both need an authenticated coordinator adapter.
- `convex/lib/renter_stock.ts:loadStockSources` supplies current all-account confirmed/ongoing stock, repairs/owner unavailability/vacations. `reservationItemUnits` supplies physical quantities; partial audited quantities are corrected separately. Unknown legacy allocations cannot be guessed into a coordinator claim.
- Website checkout currently imports `items:sharedStockForStorefront` and separately creates local whole-order holds. Amendments, cancellations, returns and prepared/unknown payment operations retain or release those local allocations through their own state machines. Every one must bind to the same central claim before it can make a stock commitment.

Required protocol:

1. Resolve the entire actual basket to canonical master items, exact quantities, per-item periods/clocks and source rental identity. Record a request fingerprint and immutable attempt identity. Existing allocations belong to their original physical evidence; same-kit extensions exclude only the same bound rental, not loosely shared accessories.
2. In one coordinator transaction, acquire or revise the complete claim against all existing allocations/claims. Replay the same request idempotently; reject changed particulars. A lost response must recover the same receipt rather than creating another claim. Both apps must use this transaction before payment/provider approval; a later mirror write cannot supply the guarantee.
3. Carry the claim through prepared/open/paid/confirmed/collected lifecycle states. Once provider execution may have begun, expiry alone is insufficient to release it. Unknown payment/approval/cancellation/refund outcomes remain occupied until attested terminal state. Return conditions and repair custody remain physical constraints even when financial settlement is separate.
4. Reconcile source confirmed allocations against claims without counting a mirrored booking twice. Keep overdue custody occupied until actual return. Provider imports must record conflicts from out-of-band confirmations honestly; they cannot retroactively prevent external actions already accepted outside the coordinator.
5. Wire every stock-affecting website and Hygglo writer, including manual and automated approval, date/item changes, extensions, rescheduling, cancellation, expiry and return. Preserve existing messaging/payment/publishing/return gates. Inventory snapshots and cart/replacement quotes read the same authority but do not manufacture claims for browsing or marketing demand.
6. Before rollout, reconcile current legacy allocations from source evidence; register owner/service bindings and the exact production project pair. Test concurrent last-unit requests across both apps, request replay/changed payload, lost create response, provider uncertainty, mutation rollback/recovery, amendment mixtures and return/repair transitions. Then verify the deployed aliases, actual authenticated callers and real resulting calendars/notifications.

The authority adds a network dependency to checkout/provider approval. Failures must offer recovery of the saved request and preserve already-started operations rather than falling back to independent writes. No new paid provider or silent quality downgrade is proposed. The whole guarantee remains unproven until every relevant writer participates and actual paired acceptance passes. Source snapshots, private handler fixtures and green local builds do not establish it.
