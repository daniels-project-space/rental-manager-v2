# Read-only replacement quotes through Mastra

A fresh canonical bot run correctly retrieved the TTArtisan's manual focus and the owned Sony 16–35's dated £40 quote, but then offered a replacement booking total using only an individual item quote. The Native basket quote tool handled additions only. Separately, the price guard carried the previous Sony identity into the old item’s parenthesized “TTArtisan (£42)” amount.

`quote_booking_replacement` now exposes the shared Native equipment proposal preparation through Mastra. It selects exact current commercial listing units, retains the rest of the order, resolves the selected offerings and their required mount accessories, prices the complete proposed basket at the existing dates and checks all physical components together. It never writes an order. Missing/ambiguous current listings, excessive removal quantities, collected/closed rentals, unowned offerings, incomplete mappings, unknown compatibility and unverified stock are refused. Real bookings remain gated. The server request owns thread/account identity.

Receipts preserve base, removed and added members separately. The price adapter validates the resulting member equation, dates and line sums; the guard checks the base against the actual requested basket and independently checks replacement membership. Replacement receipts cannot become addition-consent records. Item prices still cannot prove a complete booking total. Parenthesized item labels use the shared confident name matcher over distinct Native identities, so unknown models and ambiguous shorthand cannot borrow a prior price. Conditional totals remain proposals.

Verification uses focused price/evidence/scope/mount/date checks and project/backend typechecks. The deployed actual Mastra tool was invoked against an owned Lab booking, with all three reads reaching Native. Its quote replaced £42 with £40, rejected excessive and missing removal selections, ignored a foreign caller-supplied thread in favor of the server scope, and left the order unchanged. The previously captured actual model output was replayed with the new Native basket receipt: price claims passed, Native draft saving and fresh stock approval passed, and fixtures were cleaned. No new model generation or real rental writes were used. Proof: `/root/rental-replacement-native-proof.json`.
