# Partial audited kit quantities reach shared stock correctly

Fully audited reservations already multiplied each kit component by the booked listing quantity. The partial-audit branch instead set the component's per-kit quantity directly, and later audited listings overwrote earlier contributions. A separate unoverridden product mapped to the same physical item was also lost when the audited quantity replaced legacy attribution.

Partial audits now aggregate the physical components of every audited listing, scaled by its booked quantity. Recorded supplied adapters follow the same per-kit expansion as the fully audited branch. An independent unoverridden product mapped to an audited physical item contributes its recorded leading kit quantity multiplied by booked listing quantity. The aggregate then replaces legacy attribution for those audited items; unrelated legacy units remain unchanged.

Booked listing quantities and audited component quantities must be positive safe integers. Invalid fractions, zero/negative values and overflowing products/sums fail rather than becoming plausible physical counts after multiplication. Explicit empty audit components remain the existing owned-nothing/marketing decision; this change does not invent equipment for them.

Actual private snapshot/quote tests use a controlled reservation with two kits of two bodies, two kits of one body, and two independent two-body listings: ten bodies occupied out of twelve, leaving two free. The prior actual 8346819 mapper, bundled into the unchanged actual snapshot pipeline, emits one occupied and eleven free (`/tmp/rm-partial-kit-quantities-negative.json`). Current code emits ten occupied and two free. Reversing listing order preserves the same physical windows. Tests also cover supplied plus separately booked adapters and invalid/overflowing quantities.

These are real application functions with synthetic records, not live rental/customer acceptance. Full local suite passes: 142 files, 2168 tests, 14 existing skips.
