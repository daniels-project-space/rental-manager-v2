# Device-bound push renewal

Background push renewal previously posted through an owner-session-protected save endpoint. That would fail once the dashboard cookie expired after authenticated cutover. The public VAPID configuration route already uses private service transport; the session dependency was on saving the replacement subscription. This does not prove login expiry caused the owner's current one-to-two-hour report while owner enforcement remains off.

The bell now creates a random 256-bit device credential in the same IndexedDB used by its service worker. One serialized transaction prevents simultaneous tabs from minting different credentials. Foreground owner saves register only its SHA-256 hash. The cookie-independent renewal route uses private service transport and verifies that capability against the selected registration. It permits only that installation's subscription renewal: no activation, preference changes, credential replacement or general app access. Disable deletes the registration; explicit Enable rotates the browser credential; moving delivery to another device revokes the previous hash. Existing installations enroll on their next foreground app open; legacy worker saves remain owner-protected.

A second structural failure prevented accepting fresh encryption keys on an unchanged endpoint URL after a 410 prune. The registration now retains a canonical key fingerprint, so a real key rotation can renew the same URL while an unchanged dead subscription and mere base64-format changes remain rejected. Background renewal preserves the phone's mode and user agent. Desktop heartbeats still cannot steal the selected phone.

Validation: 47 focused tests in six affected files cover registered Native mutation handlers, rejected/rotated/revoked credentials, no-owner-cookie HTTP transport, dropped activation/preference arguments, same-URL key rotation and worker restart. An actual Chrome run verifies concurrent tabs share one credential, explicit Enable rotates it, browser restart retains it, and the real worker shares that IndexedDB. Frontend build and backend typecheck/deploy passed; Graphify updated. No paid model calls. Real push destination was never replaced by a test fixture. Browser proof: /root/rental-push-credential-browser-proof.json.

Physical iPhone delivery across multiple hours remains unverified. iOS subscription events and permission behavior still require device acceptance; this release does not promise OS-level delivery guarantees. The actual selected phone is active in my_share (earnings-only) mode. The latest sampled 40 events were 26 renter messages, 13 new requests and one response-rate warning: all preference-suppressed, none delivery-exhausted. The owner's async choice between all updates with own-share amounts and earnings-only remains pending; this release preserves that setting. The all-updates-plus-own-share choice needs an explicit preference representation if selected.

Owner access cutover and the broader bot/inventory/stage/metrics audit remain active. Real Hygglo activation, messages or booking writes require separate explicit written consent.
